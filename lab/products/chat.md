# 对话 · 聊天 子系统说明（chat.html）

> 来源：另一条对话完成的 React + Vite `chat-app`（微信风 1:1 聊天）。
> 集成方式：重建为**单文件 HTML**，与工作台既有的「单文件 vanilla-HTML」体系保持一致，而非嵌入需构建的 React 包。

---

## 一、这个子系统是什么

一个微信风格的 1:1 聊天工具，主题贴合「AI 正向引导、有正反馈、和谐家庭关系」的叙事（种子对话正是「洋哥激励研究生亲戚做睡眠小程序 + 短视频分享」那段）。

集成位置：

- 文件：`lab/products/chat.html`
- 入口：`lab/index.html` 产品库（计数 30 → 31）、`index.html` 工具区（💬 CHAT 图标）
- 交叉入口：习惯锻造台「🌙 睡眠」视图顶部「💬 和鼓励你的人聊聊」

---

## 二、已实现功能

| 能力 | 说明 |
|---|---|
| 消息类型 | 文本 / 表情 / 图片(base64) / 文件 / 语音 |
| 语音 | 支持真实 `MediaRecorder` 录音；环境不支持时自动模拟 |
| 消息操作 | 撤回 / 转发 / 删除（右键或长按弹出菜单） |
| 界面 | 深色模式、快捷回复、对方「输入中」动画、连接状态点 |
| 数据 | 复用同一存储 key `chat-app-messages-v1`，**保留原有对话** |
| 连接 | 可选 WebSocket 端点（设置里填，连上走真实回复，否则本地模拟） |
| 其它 | 导入 / 导出对话 JSON、清空对话 |

## 三、WS 服务端：加不加有什么影响

源目录里确有 `chat-app/ws-server.js`，但它是一个**演示服务端**：收到消息后延迟 1~1.8 秒，回一条**随机的 canned 自动回复**（与客户端 mock 同一份 `AUTO_REPLIES`），并广播给所有连上的客户端。**它不区分两个真人、不存真实消息、也不在外网可达。**

| 维度 | 不加（默认 mock） | 加（跑 `npm run server`） |
|---|---|---|
| 回复内容 | 本地循环假回复 | 还是同一份假回复（服务端也是 canned） |
| 连接状态 | 显示「模拟」 | 显示「已连接」 |
| 是否需要后端 | 不需要，纯本地离线 | 要 `npm install` + 常驻一个 Node 进程 |
| 跨端真实对话 | ❌ | ❌（仍是对自己广播） |
| 唯一真有用的点 | — | 开**两个标签页**能互相广播同步，可当双窗口草稿本 |

**结论：**

- 就「本地用、记自己这边的对话、存图片/文件/语音」而言，**不加完全够用**，还省掉常驻进程和依赖安装。
- `chat.html` 已原生支持 WS——设置里粘贴 `ws://localhost:8787` 即可连接，无需改代码。
- 无论加不加，**现在都聊不了真正的洋哥**——因为服务端不会区分两个人、不存真实消息、也不在外网可达。

## 四、如果想「真的和洋哥实时聊」

需要的不是这个 demo 服务端，而是：

1. **双用户中继服务**：用房间 / 登录区分「我」与「洋哥」，真实转发并持久化消息；
2. **部署到外网 + `wss://`（加密）**：`ws://` 是明文且仅 localhost 可达，远程必须上 wss 并配域名 / 反代；
3. **给洋哥一个客户端**：可以是同一个 `chat.html`，或任意 WS 客户端。

这是另一个量级的工程，与本次静态集成是两回事。

---

## 五、使用方式

1. 打开 `lab/products/chat.html`；
2. 点右上角 ⚙️ 设置：可改「我的昵称 / 对方昵称 / WebSocket 地址」；
3. 留空 WS 地址 = 本地模拟自动回复；填入 `ws://localhost:8787`（且对应服务端在跑）= 走真实 socket；
4. 支持导出 / 导入对话备份、清空对话。
